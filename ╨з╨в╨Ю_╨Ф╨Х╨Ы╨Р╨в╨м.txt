───────────────────────────────────────────────────────────────
ШАГ 1. ЗАМЕНИТЬ ФАЙЛЫ ПРОЕКТА
───────────────────────────────────────────────────────────────

1. Распакуйте архив CarSpot_v1.zip

2. Откройте C:\carspot_project

3. УДАЛИТЕ оттуда старые папки и файлы:
      app\          (всю папку целиком)
      Procfile
      Dockerfile
      requirements.txt
      docker-compose.yml

   Папку .git НЕ ТРОГАЙТЕ — она нужна для git push.
   Папку CarSpot-iOS тоже оставьте.

4. Скопируйте в C:\carspot_project всё содержимое архива:
      app\
      tests\
      Dockerfile
      Procfile
      requirements.txt
      docker-compose.yml
      reset_db.py
      seed_demo.py
      README.md
      .gitignore
      .env.example


───────────────────────────────────────────────────────────────
ШАГ 2. ПРОВЕРИТЬ ЛОКАЛЬНО (5 минут)
───────────────────────────────────────────────────────────────

Откройте PowerShell:

    cd C:\carspot_project
    pip install -r requirements.txt
    python tests\test_full_flow.py

Должно вывести:  ПРОЙДЕНО: 117    ПРОВАЛЕНО: 0

Затем:

    python seed_demo.py
    uvicorn app.main:app --reload

Откройте в браузере:  http://localhost:8000/docs

Войдите любым демо-аккаунтом (пароль Demo12345):
    namig / dato / aysel / giorgi

Посмотрите, как всё работает, прежде чем деплоить.


───────────────────────────────────────────────────────────────
ШАГ 3. ПОЧИНИТЬ DATABASE_URL НА RAILWAY  ← САМОЕ ВАЖНОЕ
───────────────────────────────────────────────────────────────

Сейчас переменная сломана: в неё склеены две строки через пробел.
Из-за этого приложение и падало.

1. Railway → ваш сервис → вкладка Variables

2. Найдите DATABASE_URL и УДАЛИТЕ её полностью

3. Нажмите + New Variable и создайте заново:

       Имя:      DATABASE_URL
       Значение: ${{Postgres.DATABASE_URL}}

   Пишите РОВНО ТАК, вместе со скобками. Railway сам подставит
   настоящий адрес базы.

   Если сервис базы у вас называется не Postgres — подставьте
   его имя, например ${{postgres-production.DATABASE_URL}}

4. Добавьте ещё одну переменную:

       Имя:      SECRET_KEY
       Значение: любая длинная случайная строка (30+ символов)

5. Переменную PORT можно удалить — Railway передаёт её сам.


───────────────────────────────────────────────────────────────
ШАГ 4. СБРОСИТЬ СТАРЫЕ ТАБЛИЦЫ В БАЗЕ
───────────────────────────────────────────────────────────────

В базе лежат таблицы от прошлых попыток (photos_v2 и другие,
с неправильными колонками). Сами они не исправятся.

1. Railway → сервис Postgres → Variables
2. Скопируйте значение DATABASE_PUBLIC_URL
   (именно PUBLIC — он доступен с вашего компьютера)

3. В PowerShell:

    cd C:\carspot_project
    $env:DATABASE_URL="сюда_вставить_скопированный_адрес"
    python reset_db.py

4. Скрипт спросит подтверждение — введите:  yes

Он удалит все старые таблицы и создаст 14 новых, правильных.


───────────────────────────────────────────────────────────────
ШАГ 5. ЗАЛИТЬ НА GITHUB
───────────────────────────────────────────────────────────────

    cd C:\carspot_project
    git add -A
    git commit -m "CarSpot API v1.0 - полная версия"
    git push

Railway начнёт сборку автоматически. Подождите 2-3 минуты.


───────────────────────────────────────────────────────────────
ШАГ 6. ПРОВЕРИТЬ
───────────────────────────────────────────────────────────────

Откройте:  https://ваш-домен.up.railway.app/health

Должно вернуть:

    {"status":"ok","database":"ok","version":"1.0.0"}

Если database: "unavailable" — значит DATABASE_URL всё ещё
неправильная, вернитесь к шагу 3.

Затем откройте /docs и зарегистрируйте живого пользователя.

───────────────────────────────────────────────────────────────
ОДНО ПРЕДУПРЕЖДЕНИЕ ПРО ФОТО
───────────────────────────────────────────────────────────────

Railway стирает загруженные файлы при каждом передеплое —
это особенность платформы, а не ошибка кода.

Для реального запуска нужно подключить S3 или Cloudinary.
Менять придётся только одну функцию _save_file() в файле
app/api/photos.py — остальной код трогать не надо.

До запуска в App Store это можно отложить.


───────────────────────────────────────────────────────────────
ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
───────────────────────────────────────────────────────────────

Railway → сервис → вкладка Deploy → скопируйте последние
20-30 строк логов и пришлите их.

В новой версии приложение не падает молча: ошибки видны
в логах с понятным текстом, а /health показывает, жива ли база.
